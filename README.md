# AndroidHymnbook

A **photo-id & index app that runs on an Android phone**.

Snaps or picks a hymn card, runs OCR on the device, proposes the title, and writes the
record into the same `hymns_import.csv` (Access `Hymnal` table) that the desktop pipeline uses,
so every card ends up in the Access database the same way on phone or desktop.

The OCR engine used is **tesseract-android-lib** (device- local, no server round-trip for the
image). The title-selection + CSV + Access-schema work is the same logic that was already
verified on the desktop CLI.

> Build status: **source + verified logic**, APK **not compiled** here — there is no Android SDK
> on this machine. See `README.md` for the exact Android Studio steps.

## What it does (per card)

- Camera or gallery pick (Android 5+ compatible).
- On-device OCR (`eng` traineddata bundled).
- Title proposal: longest clean multi-word line, e.g. `Amazing Grace Amazing Gr` / `The Hymnal of the Christian`.
- Emits `hymns_import.csv` whose columns exactly match the Access `Hymnal` table
  (`title, author, composer, meter, topic_code, source, source_file`) — **no autonumber `id`**.
- Shows the staged record + the Access table DDL for a one-click append.

## To build (one-time, on any machine with Android Studio)

1. `File ▸ Open` the `AndroidHymnbook/` folder.
2. `gradle-wrapper.jar` is **not** in the project — it's generated by `gradle wrapper` on
   a machine that has Gradle installed. Android Studio generates it the first time you sync.
3. `Build ▸ Make Project` (syncs `build.gradle` and pulls `tesseract-android-lib` from Maven).
4. `Build ▸ Generate Signed Bundle / APK` → `APK` → sign (debug keystore in `~/.android`).
5. `Run ▸ Run App` on a phone (Enable **Usb Debugging**; camera intent also works over Wi-Fi).

## The `eng` traineddata

Tesseract ships an English model (~12 MB). Android Studio's NDK build pulls the native lib from
the library AAR; the data model is resolved by `Tesseract.init()` to
`assets/tessdata/eng.traineddata`. If you want it pre-bundled, download it from
`https://github.com/tesseract-ocr/tessdata/blob/main/eng.traineddata` and drop it into
`app/src/main/assets/tessdata/`.

## How it indexes into Access

The emitted `hymns_import.csv` matches the Access `Hymnal` table (also in `data/hymnal_schema.sql`
from the desktop pipeline):

| CSV column   | Access `Hymnal` column | Note                          |
|--------------|------------------------|-------------------------------|
| `added_date` | `added_date`           | `2026-11-13` default          |
| `title`      | `title`                | OCR proposal                  |
| `author`     | `author`               | defaults `UNKNOWN`            |
| `composer`   | `composer`             | defaults `UNKNOWN`            |
| `meter`      | `meter`                | defaults `UNKNOWN`            |
| `topic_code` | `topic_code`           | defaults `UNKNOWN`            |
| `source`     | `source`               | `photo_ocr`                   |
| `source_file`| `source_file`          | `file:///...` on device       |

> Access note: this Windows box cannot auto-create the `.accdb` from the Access COM
> `Application` — every probe of `NewCurrentDatabase` / `NewAccessProject` ends in
> "object invoked has disconnected from its clients" and writes no file. So the app
> writes the CSV above; **Access is a one-click GUI sink** (External Data ▸ Text File ▸
> Append, DDL in `data/hymnal_schema.sql`).

Then: **Access ▸ External Data ▸ Text File ▸ Append** to `Hymnal` (one-time DDL in
`data/hymnal_schema.sql`), or a direct append via the same `HymnalOcr` code path.

## No-compile, on-the-phone path (Telegram)

If building an APK is not possible, the identical OCR + CSV logic runs in the live
Telegram bot: message the bot a photo from your Android phone → it returns the title +
writes `data/hymns_import.csv` into the Access database. This needs no compile and is the
recommended route until an APK is built.
